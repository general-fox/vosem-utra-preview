# Восемь утра — рабочий проект

Это единственный рабочий проект сайта: дизайн, меню, админка и код для REG.RU.
С 1 октября 2026 года основной режим — сайт-каталог без доставки и онлайн-заказов.
Код доставки сохранён как отключаемый модуль; обычная сборка его не включает.
Инструкция по загрузке: [сайт без доставки](docs/catalog-upload.md).
Повторное подключение: [модуль доставки](modules/delivery/README.md).
Рабочая папка на этом компьютере: `C:\Websites\vosem-utra\github-preview`.
На другом компьютере путь может отличаться; его показывает GitHub Desktop → Repository → Show in Explorer.
Существующий репозиторий: [general-fox/vosem-utra-preview](https://github.com/general-fox/vosem-utra-preview).
Новый репозиторий создавать не нужно.

## Меню и админка

11 ноября 2026 года меню обновлено из предоставленного серверного `BCKP.zip`.
В локальной админке сохранены все 66 позиций, включая 9 скрытых. Публичный каталог
содержит 57 позиций и 39 фотографий: завтраки, ужины, напитки, супы и сэндвичи/вафли.
Названия, цены, порядок и фотографии сохранены из серверной копии без переработки.
Автоматической синхронизации с хостингом или Яндексом нет.
Источник, резервная копия и ограничения будущей публикации описаны в
[инструкции импорта](docs/server-import-2026-11-11.md).

Панель: `/admin.html`. «Добавить блюдо» открывает ручной редактор названия,
описания, цены, группы и фотографии JPG/PNG/WebP до 5 МБ. Блюда можно менять
и удалять. Группы сайта одноуровневые: их можно добавлять, удалять и переставлять.
Выбранная группа определяет размещение блюда на сайте; переключатель видимости
позволяет скрыть блюдо, сохранив его в админке. Вход — по почте и паролю,
восстановление пароля — кодом по почте. Яндекс ID и второй фактор отключены.
Интерфейс кассы и синхронизация в режиме каталога отключены.

## Корзина и оформление — сохранённый отключённый модуль

При явном включении доставки корзина хранит в браузере только идентификаторы блюд и количество. Страница
`checkout.html` поддерживает самовывоз, доставку, ближайшее время и выбор слота.
PHP рассчитывает сумму в копейках, выдаёт расчёт на 5 минут и сохраняет заявку
транзакционно в приватной SQLite. Повтор той же отправки возвращает тот же заказ.
Онлайн-оплаты нет; сохранённая заявка имеет статус «Ожидает подтверждения».

По умолчанию `npm run dev` запускает сайт-каталог и PHP для админки.
Тестовые заказы доступны только при запуске `npm run dev:delivery`:
нужны PHP 8.3+ и PDO SQLite (`PHP_BIN` позволяет указать путь). На Windows
подхватывается соседний `.tools/php/php.exe`. Условия явно демонстрационные;
вводить только вымышленные данные. Привязка администратора не меняется.
GitHub Pages и обычная сборка `npm run build` в `dist/` показывают каталог;
корзина и оформление заказов отключены.

Для доставки на REG.RU нужна отдельная сборка `npm run build:reg:delivery`
или `npm run build:reg:test:delivery` для тестового стенда, а также приватный
`orders-config.php` с согласованными условиями. Бот и приложение сотрудников реализованы на PHP:
вход через проверенные данные Telegram, распределение и согласование заказов,
принятие, история и очередь уведомлений. Демонстрация с вымышленными заказами —
`staff-demo.html`; действующее приложение — `staff.html`. Для подключения нужны
приватные настройки, числовые ID сотрудников, HTTPS и cron. Отправитель
интегратору будет подключён отдельно. Подробнее: [Telegram](docs/telegram.md),
[работа и проверка доставки](docs/delivery.md).

## Запустить на компьютере

Для локальной разработки используйте действующие почту и пароль администратора.
Откройте терминал в этой папке:

```powershell
npm run dev
```

Сайт: <http://127.0.0.1:5173/>, админка: <http://127.0.0.1:5173/admin.html>.
Если порт занят, смотрите адрес в терминале. Остановить сервер: Ctrl+C.
`npm start` делает то же самое. Исходники редактируются здесь; пересобирать сайт
после каждой локальной правки не нужно.

На новом компьютере нужны Node.js 24+, npm, PHP 8.3+ с OpenSSL, GD, PDO SQLite
и cURL. Перед первым запуском — `npm ci`. Пути PHP задаются в приватном
`.env.local`. После обновления со старой версии первый запуск один раз запрашивает
действующий пароль в терминале для переноса аккаунта в PHP. Пароль и привязка
аутентификатора сохраняются; вводить пароль в чат не нужно.
Пароли и рабочее меню с другого компьютера сами через Git не появятся:
для них предусмотрен отдельный защищённый перенос.

В текущем режиме каталога вход выполняется по почте и паролю; второй фактор
отключён. В архиве есть более новая собранная версия интерфейса админки, но её
исходников нет. Локальную админку при импорте данных не реконструировали:
перед выпуском на домен нужно сохранить действующий серверный интерфейс,
как описано в [инструкции импорта](docs/server-import-2026-11-11.md).

## Что где лежит

| Папка / файлы | Назначение |
| --- | --- |
| HTML, CSS, JS в корне | Страницы, оформление и поведение сайта |
| `assets/` | Используемые изображения, шрифты и их лицензия; TTF нужны для повторной упаковки WOFF2 |
| `public/` | Начальное меню, его фотографии и публичные служебные файлы |
| `hosting/` | Серверный код PHP и страницы работающей формы клуба для REG.RU |
| `server/` | Модули сборки/SEO, локальное подключение PHP и совместимость со старым Node-хранилищем |
| `scripts/`, `tests/`, `docs/` | Сборка, проверки и инструкции |
| `.data/php-runtime/` | **Рабочие локальные аккаунты, меню и загруженные фото — не Git** |
| `.data/private-backups/`, `.data/private-exports/`, `.data/transfer-keys/` | Приватные резервные копии, перенос и отдельные ключи — не Git |
| `dist-reg/` | Собранные файлы для REG.RU, создаются заново — не редактировать |
| `dist/`, `dist-hosting/`, `node_modules/` | Автоматически создаваемые файлы — не редактировать |

Название `hosting/legacy-public/` означает совместимые страницы действующей
формы клуба, а не мусор: они входят в сборку. `hosting/legacy-private/legal-versions/`
содержит прежние редакции документов для сохранённых согласий; их тоже не удалять.

## GitHub Desktop: продолжать существующий проект

1. Выберите **vosem-utra-preview**.
2. Через **Repository → Show in Explorer** проверьте рабочую папку.
3. Перед началом работы на любом компьютере нажмите **Fetch origin**, затем
   **Pull origin**, если появились обновления.
4. После работы проверьте изменения, выполните проверки, сделайте **Commit**,
   затем **Push origin**, прежде чем переходить на другой компьютер.
5. Если возник конфликт, объедините нужные изменения обеих версий и удалите
   все служебные строки конфликта. `npm test` проверяет, что таких строк не осталось.

Не создавайте новый репозиторий и не добавляйте родительскую папку рабочего проекта.
В Git идут исходники и нужные публичные ресурсы. `.data`, `.env.local`, ключи,
пароли, базы, архивы и сборки исключены из Git. Не добавляйте их принудительно.

[Предпросмотр заказчика](https://general-fox.github.io/vosem-utra-preview/) остаётся
по прежнему адресу. Для текущего способа публикации Pages используются
`main → / (root)`, `.nojekyll` и исходные страницы. Смена папок публикации не нужна.
GitHub Pages — статический просмотр каталога: корзина и оформление отключены,
PHP, вход в админку и отправка анкет там не работают. Приложение сотрудников,
рабочий бот и обработка заказов относятся к отдельному режиму доставки.
Страницы предпросмотра сохраняют `noindex`.

Изменения блюд через **локальную админку** записываются в `.data/php-runtime/`,
а не автоматически в GitHub. Это специально защищает аккаунты и рабочие данные.
На REG.RU они переносятся отдельно, по инструкции ниже. Не копируйте всю `.data`
в `public/` ради публикации меню.

## Сборка для REG.RU

```powershell
npm test
npm run build:reg
npm run build:reg:test
npm run test:catalog
```

Результат проверки сборки находится в **`dist-reg/`**. После импорта от 11 ноября
это пока не пакет для загрузки на домен: сначала нужны запланированные изменения
дизайна и проверка сохранения обновлённой серверной админки.

Обычная структура сборки:

- `site/` — в публичную папку домена;
- `vosem-utra-private/app/` и новые редакции `legal-versions/` — в приватную папку
  рядом с доменом, как описано в [инструкции REG.RU](docs/reg-upload.md).

Это **выход сборки**, не вторая рабочая копия. На хостинге используется PHP;
постоянный Node.js не нужен. Существующие настройки, аккаунты, меню, заказы,
ключи FlexBonus/reCAPTCHA и согласия не заменяйте новой сборкой.
GitHub push не обновляет REG.RU.

Тест подтверждения телефона через uCaller собирается отдельно:
`npm run build:reg:test:ucaller`. Он предназначен для test888.ru и не отправляет
анкету в FlexBonus. Настройки находятся в закрытом `ucaller-config.json`,
поэтому на другой компьютер через GitHub не переносятся.
Подключение и различия режимов: [инструкция uCaller](docs/ucaller-test.md).
Для проверки сохранённого модуля доставки используются отдельная сборка
`npm run build:reg:delivery` и `npm run test:reg`.

Первый перенос аккаунтов без смены паролей и QR: `npm run private:export`.
Резервная копия локальных данных: `npm run private:backup`.
Порядок восстановления и ограничения — [в инструкции переноса](docs/local-runtime-and-transfer.md).
Ключ резервной копии храните отдельно от пакета. Заказы на REG.RU по умолчанию
выключены до согласования условий; онлайн-оплата ещё не подключена.

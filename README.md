## Корзина и оформление

Корзина хранит в браузере только идентификаторы блюд и количество. Страница
`checkout.html` поддерживает самовывоз, доставку, ближайшее время и выбор слота.
PHP рассчитывает сумму в копейках, выдаёт расчёт на 5 минут и сохраняет заявку
транзакционно в приватной SQLite. Повтор той же отправки возвращает тот же заказ.
Онлайн-оплаты нет; сохранённая заявка имеет статус «Ожидает подтверждения».

Локально `npm run dev` автоматически запускает PHP для тестовых заказов:
нужны PHP 8.3+ и PDO SQLite (`PHP_BIN` позволяет указать путь). На Windows
подхватывается соседний `.tools/php/php.exe`. Условия явно демонстрационные;
вводить только вымышленные данные. Привязка администратора не меняется.
GitHub Pages показывает интерфейс и корзину, но не сохраняет заказы.

На REG.RU приём по умолчанию выключен: нужен приватный `orders-config.php`
с согласованными условиями. Бот и приложение сотрудников реализованы на PHP:
вход через проверенные данные Telegram, распределение и согласование заказов,
принятие, история и очередь уведомлений. Демонстрация с вымышленными заказами —
`staff-demo.html`; действующее приложение — `staff.html`. Для подключения нужны
приватные настройки, числовые ID сотрудников, HTTPS и cron. Отправитель
интегратору будет подключён отдельно. Подробнее: [Telegram](docs/telegram.md),
[работа и проверка доставки](docs/delivery.md).

## Что где лежит

| Папка / файлы | Назначение |
| --- | --- |
| HTML, CSS, JS в корне | Страницы, оформление и поведение сайта |
| `assets/` | Используемые изображения, шрифты и их лицензия; TTF нужны для повторной упаковки WOFF2 |
| `public/` | Начальное меню, его фотографии и публичные служебные файлы |
| `hosting/` | Серверный код PHP и страницы работающей формы клуба для REG.RU |
| `server/` | Модули сборки/SEO, локальное подключение PHP и совместимость со старым Node-хранилищем |
| `scripts/`, `tests/`, `docs/` | Сборка, проверки и инструкции |
| `.data/php-runtime/` | **Рабочие локальные аккаунты, меню и загруженные фото — не Git** |
| `.data/private-backups/`, `.data/private-exports/`, `.data/transfer-keys/` | Приватные резервные копии, перенос и отдельные ключи — не Git |
| `dist-reg/` | Собранные файлы для REG.RU, создаются заново — не редактировать |
| `dist/`, `dist-hosting/`, `node_modules/` | Автоматически создаваемые файлы — не редактировать |

Название `hosting/legacy-public/` означает совместимые страницы действующей
формы клуба, а не мусор: они входят в сборку. `hosting/legacy-private/legal-versions/`
содержит прежние редакции документов для сохранённых согласий; их тоже не удалять.

## GitHub Desktop: продолжать существующий проект

1. Выберите **vosem-utra-preview**.
2. Через **Repository → Show in Explorer** проверьте папку:
   `C:\vosem-utra\github-preview`.
3. Проверьте изменения, сделайте **Commit**, затем **Push origin**.

Не создавайте новый репозиторий и не добавляйте родительскую папку `C:\vosem-utra`.
В Git идут исходники и нужные публичные ресурсы. `.data`, `.env.local`, ключи,
пароли, базы, архивы и сборки исключены из Git. Не добавляйте их принудительно.

[Предпросмотр заказчика](https://general-fox.github.io/vosem-utra-preview/) остаётся
по прежнему адресу. Для текущего способа публикации Pages используются
`main → / (root)`, `.nojekyll` и исходные страницы. Смена папок публикации не нужна.
GitHub Pages — статический просмотр: PHP, вход в админку и отправка анкет там
не работают. Страницы предпросмотра сохраняют `noindex`.

Изменения блюд через **локальную админку** записываются в `.data/php-runtime/`,
а не автоматически в GitHub. Это специально защищает аккаунты и рабочие данные.
На REG.RU они переносятся отдельно, по инструкции ниже. Не копируйте всю `.data`
в `public/` ради публикации меню.

## Сборка для REG.RU

```powershell
npm test
npm run build:reg
npm run test:reg
```

Актуальная сборка всегда в **`dist-reg/`**:

- `site/` — в публичную папку домена;
- `vosem-utra-private/app/` и новые редакции `legal-versions/` — в приватную папку
  рядом с доменом, как описано в [инструкции REG.RU](docs/reg-upload.md).

Это **выход сборки**, не вторая рабочая копия. На хостинге используется PHP;
постоянный Node.js не нужен. Существующие настройки, аккаунты, меню, заказы,
ключи FlexBonus/reCAPTCHA и согласия не заменяйте новой сборкой.
GitHub push не обновляет REG.RU.

Первый перенос аккаунтов без смены паролей и QR: `npm run private:export`.
Резервная копия локальных данных: `npm run private:backup`.
Порядок восстановления и ограничения — [в инструкции переноса](docs/local-runtime-and-transfer.md).
Ключ резервной копии храните отдельно от пакета. Заказы на REG.RU по умолчанию
выключены до согласования условий; онлайн-оплата ещё не подключена.

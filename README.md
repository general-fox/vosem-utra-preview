# Восемь утра — демоверсия

Рабочая папка этой версии на этом компьютере: `C:\vosem-utra\github-preview`.

Админка, меню и заказы локально и на REG.RU работают на одной PHP-серверной части.
Актуальные инструкции: [локальный запуск, перенос без смены паролей и резервные копии](docs/local-runtime-and-transfer.md).

## Завтраки и панель управления

Пункт «Меню» ведёт к каталогу 19 завтраков с ценами, составом и фильтрами.
Названия, цены и 13 фотографий перенесены из [меню Яндекс Карт](https://yandex.ru/maps/org/vosem_utra/133294557510/menu/)
28 сентября 2026 года (в источнике: обновлено 16 сентября). У шести блюд фотографии
в источнике отсутствуют: они показаны текстовым списком. Повторяющийся рекламный
текст заменён краткой формулировкой из названия; недостающий состав не придуман.
Мак и чиз и тартар не включены в раздел завтраков. Автоматической синхронизации
с Яндексом нет: дальнейшие изменения выполняются в панели.

Панель: `/admin.html`. Добавление, редактирование, загрузка JPG/PNG/WebP до 5 МБ,
изменение цены и порядка, скрытие/публикация и удаление блюд. Изменения сохраняются
на сервере и видны после обновления публичного меню или возвращения в его вкладку.
Блюда с фотографиями и без фотографий показаны в отдельных группах; порядок
действует внутри каждой группы. Доступность для заказа настраивается отдельно
от публикации: временно недоступное блюдо остаётся в меню.

## Корзина и оформление

Корзина хранит в браузере только идентификаторы блюд и количество. Страница
`checkout.html` поддерживает самовывоз, доставку, ближайшее время и выбор слота.
PHP рассчитывает сумму в копейках, выдаёт расчёт на 5 минут и сохраняет заявку
транзакционно в приватной SQLite. Повтор той же отправки возвращает тот же заказ.
Онлайн-оплаты нет; сохранённая заявка имеет статус «Ожидает подтверждения».

Локально `npm run dev` автоматически запускает PHP для админки, меню и тестовых заказов:
нужны PHP 8.3+ и PDO SQLite (`PHP_BIN` позволяет указать путь). На Windows
подхватывается соседний `.tools/php/php.exe`. Условия явно демонстрационные;
вводить только вымышленные данные. Привязка администратора не меняется.
GitHub Pages показывает интерфейс и корзину, но не сохраняет заказы.

На REG.RU приём по умолчанию выключен: нужен приватный `orders-config.php`
с согласованными условиями. Telegram, рабочее место сотрудников и отправка
интегратору будут подключены по отдельным ТЗ. Подробнее:
[работа и проверка доставки](docs/delivery.md).

## Локальная разработка и вход

Для локальной разработки нужны PHP 8.3+ (OpenSSL, GD, PDO SQLite) и Node.js 24+.
Первый запуск переносит старое локальное хранилище, сохраняя его резервную копию;
для настроенных Node-аккаунтов может потребоваться скрытый ввод текущего пароля.
Запустите сайт:

```powershell
npm run dev
```

Дальше всё выполняется на `/admin.html`: введите действующий логин и пароль,
укажите почту `v.utra@yandex.ru`, подключите Яндекс ID (Ключ) по QR и подтвердите
6-значный код на той же странице. Если прежний пароль короче 15 символов,
панель предложит новый. Сохраните показанные резервные коды.
Подключение выполняется один раз; последующие входы требуют только почту,
пароль админки и текущий код приложения. Командная строка для входа не нужна.
Одноразовые резервные коды показываются один раз. Пароль хранится как Argon2id-хеш
(bcrypt при отсутствии Argon2id),
секрет второго фактора — в зашифрованном виде. В production обязательны MFA,
ключ шифрования и HTTPS-настройки; без них админка закрыта, публичное меню доступно.
Cookie HttpOnly/SameSite=Strict/Secure (HTTPS), время бездействия 30 минут,
абсолютный срок 8 часов. Запись проверяет origin, CSRF и версию меню.
Подробнее: [безопасность входа](docs/admin-security.md).
Дополнительного сотрудника можно добавить локально через `npm run admin:add -- email`.
Первый вход требует смены временного пароля и собственной привязки TOTP; основной
аккаунт не заменяется. После пароля и подтверждённого TOTP браузер автоматически
запоминается на 30 дней: после перерыва нужен только код. Выход сбрасывает
запоминание. Пароли, привязки и доверенные устройства в Git не попадают.

Для **обычного хостинга REG.RU** подготовлена серверная часть на PHP 8.3+:
вход с MFA, сохранение меню, фото и актуальный HTML для поисковиков.
На сервере нужны OpenSSL, GD, cURL, PDO SQLite и доступ на запись в приватную папку.
Постоянный процесс Node.js на хостинге не нужен.

```powershell
npm run build:reg
```

Получится `dist-reg/site/` и `dist-reg/vosem-utra-private/`. В этот комплект
включены настоящая PHP-форма клуба, cookie-интерфейс и документы прежней сборки.
Ключи интеграций, пароль и данные администратора в пакет не копируются.
Существующие приватные настройки и согласия на сервере сохраняются.
Подробный порядок: [перенос на REG.RU](docs/reg-upload.md).

Локальная разработка использует Vite для интерфейса и PHP для админки, меню и
заказов. Прежний отдельный Node-сервер сохранён только для старых проверок.
Для локального запуска:

```powershell
npm ci
# При необходимости укажите PHP_BIN и PHPRC в .env.local.
npm run dev
```

Адрес по умолчанию — `127.0.0.1:5173`. `npm start` запускает тот же локальный
режим, не production. На REG.RU устанавливается `dist-reg` с HTTPS и приватным
`admin-config.php`; постоянно работающий Node-процесс там не нужен.
Нового сотрудника добавляет только оператор командой `npm run admin:add -- email`.
Публичной регистрации администратора нет.

Рабочие данные и фотографии находятся в `.data/php-runtime/`, закрыты от HTTP
и исключены из Git. `npm run private:backup` создаёт зашифрованную резервную копию,
`npm run private:export` — пакет первого переноса без тестовых заказов.
Исходный каталог `public/data/menu.json` используется только при подготовке
нового хранилища; сборка не сбрасывает изменения администратора.
Удаление блюда не удаляет загруженное фото с диска.

GitHub Pages показывает начальный каталог, но не может запускать этот API:
админ-панель на статическом хостинге объяснит, что сервер недоступен. Для живого
управления меню используйте PHP-сборку для REG.RU; локальные изменения из `.data/` не
публикуются на Pages автоматически. При статическом просмотре используйте HTTP,
а не открытие `index.html` через `file://`.

Новые файлы: `menu.js`, `menu.css`, `public/data/menu.json`, `public/menu-images/`,
`admin.html`, `admin.js`, `admin.css`, `server/`. Источники фотографий перечислены
в `docs/menu-photo-sources.json`. Тесты API проверяют права, сохранение,
параллельные изменения, лимиты входа и загрузки, закрытые пути.

## Локальный запуск

Требуется Node.js 24+ с npm. При первом запуске: `npm install`.

```powershell
cd C:\vosem-utra\github-preview
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173/).
Сохранённые изменения автоматически отображаются в браузере.
Остановить сервер: Ctrl+C.

`npm run build` собирает все пять страниц в `dist` с `noindex` для показа заказчику.
`npm run build:hosting` собирает сайт для `https://vosem-utra.ru/` в `dist-hosting`:
canonical, метаданные карточек ссылок, разметка кофейни и меню, robots и sitemap.
Блюда включены в исходный HTML; Node-сервер обновляет его из сохранённого меню
при каждом запросе. Инструкции для Яндекса и Google: [SEO](docs/seo.md).
`npm run preview` позволяет посмотреть эту сборку локально.
Относительные пути подходят для размещения сайта в подпапке GitHub Pages.
Каталог также работает через обычный статический HTTP-сервер из корня репозитория.

## Что редактировать

- `index.html` — главная страница и тексты.
- `style.css` — фирменные цвета, общие компоненты, главная и мобильная версия.
- `registration.html`, `registration.css` — страница клуба гостей.
- `registration.js` — маска телефона и логика формы.
- `privacy.html`, `consent.html`, `legal.css` — правовые документы и их оформление.
- `site.js` — мобильная навигация и согласованное появление текста, фотографий,
  карточек и декоративных блоков. Цели отмечены `data-reveal` в HTML.
  Начальное состояние задаётся до первой отрисовки: нет вспышки «видно → скрыто».
  Появление запускается один раз при входе в экран, задержки внутри группы
  не превышают 180 мс. Фотографии декодируются перед появлением карточки.
  Если основной скрипт не загрузился, предохранитель открывает содержимое
  через 2,3 секунды. Фокус, якорные ссылки и возврат из истории не ждут анимации.
  Анимации отключаются при настройке «Уменьшение движения»; без JavaScript
  всё содержимое остаётся видимым. Поля формы не анимируются.

Декоративные звёздочки и солнца — встроенные SVG, не текстовые символы:
на iOS они не заменяются цветными эмодзи. Шторка — заранее отрисованный слой
с фирменным SVG-узором и неглубоким изогнутым краем (на мобильном ещё мягче).
Web Animations API поднимает весь слой за 1,1 секунды, меняя только transform:
без покадрового пересчёта SVG, размытия и дополнительных библиотек.
Высота закреплена через lvh, чтобы адресная строка телефона не меняла геометрию
во время подъёма. При недоступной анимации сайт открывается сразу.
Обычный свайп начинает подъём, но не обрывает его; ссылки, поля
и клавиатурный фокус доступны сразу. На мобильном ход параллакса ограничен
22 пикселями в каждую сторону у кофе и примерно 8–14 пикселями у полных
композиций блюд, с разной инерцией трёх карточек.

GitHub Pages не исполняет PHP. В этой копии форма явно помечена
`data-preview="true"`, кнопка отключена, обработчик не отправляет данные.
Для настоящей регистрации потребуется серверная версия из `../site`.
Изменения этой демоверсии не синхронизируются в `../site` автоматически.

### Обновлённая вывеска

`assets/cafe-sign-enhanced.png` — улучшенная встроенным ImageGen версия
исходного `assets/cafe-sign.png` (исходник сохранён без изменений).
Готовое изображение: 1254 × 1254. Для сайта используются WebP-версии
`assets/cafe-sign-enhanced.webp` и `assets/cafe-sign-enhanced-720.webp`;
браузер выбирает размер с учётом экрана. Это AI-обработка существующей
иллюстрации, а не документальная фотография фасада.

Промпт обработки (встроенный инструмент, без API/CLI):

> Use case: precise-object-edit. Asset type: high-resolution cafe website contact-section image. Image 1 is the edit target, not a style reference. Enhance the existing image only: restore crisp, natural detail, remove softness and compression, render at a high resolution suitable for retina displays (approximately 2048 x 2048). Preserve the exact square crop, perspective, lightbox shape and position, dark frame, red-brown brick facade, window edges, warm understated illumination and original atmosphere. Preserve the brand wordmark exactly as shown, including its particular elegant black serif letterforms; text verbatim in Cyrillic: "Восемь утра". No text replacement, no extra letters, no new objects, no redesigned architecture. Refine brick texture and frame edges gently without oversharpening or halos. Do not change the scene or add artistic stylization. Output only the enhanced existing image, not a comparison or a mockup.

Содержание сверено с исходниками; веб-адаптация включает следующие изменения:

- Подставлены уже указанные в проекте домен `https://vosem-utra.ru`
  и почта `vosem.utra@inbox.ru` вместо полей-заглушек.
- «Имя» уточнено до «фамилия, имя, отчество (при наличии)» по составу анкеты.
- Нормализованы регистр заголовков, оформление адреса/ИНН/ОГРНИП;
  определено сокращение «Оператор», добавлены ссылки и оглавление.
- Раздел 9 политики описывает технические данные демоверсии:
  корзина хранит в localStorage только идентификаторы блюд и их количество;
  оформление с подключённым API использует отдельный гостевой cookie,
  телефон и адрес в хранилище корзины не записываются;
  вход в админ-панель использует необходимый сессионный cookie,
  аналитика и рекламные пиксели не подключены; карта и Telegram — внешние ссылки.
  Форму клуба гостей в демонстрации нельзя отправить. На главной и страницах
  документов сохранена плашка cookie с выбором «Принять» / «Только необходимые».
  Выбор хранится в localStorage `vosem_cookie_choice` отдельно от корзины;
  само принятие плашки не подключает Google и не отправляет данные анкеты.
- Просмотр согласия не считается его предоставлением. В форме есть отдельный
  обязательный, изначально пустой чекбокс; политика доступна перед ним.
  Согласие не объединено с рекламными рассылками. Все страницы содержат
  доступные ссылки на оба документа и раздел cookie.

### Перед включением настоящей регистрации

Это оформление интерфейса, а не подтверждение юридической готовности сервиса.
Оператору/юристу нужно согласовать тексты и фактические процессы: состав данных,
цели и сроки, хостинг и журналы сервера, CRM/программа лояльности, получатели,
локализация баз данных и необходимость уведомлений Роскомнадзора.
Факт получения согласия и его версию необходимо фиксировать на сервере;
сервер должен отклонять анкету без согласия. Сервер регистрации в демоверсии отсутствует;
добавленный backend обслуживает только меню и админ-панель.

В `registration.js` сохранена неактивная логика Google reCAPTCHA из серверного
сайта. Сейчас она не загружается благодаря `data-preview="true"`. Нельзя просто
включить её без отдельной проверки передачи данных и cookie. После выбора
хостинга нужно проверить его заголовки Set-Cookie и фактические запросы сайта.
При добавлении необязательной аналитики/рекламных сервисов, работающих на
основании согласия, их загрузка должна происходить только после явного выбора;
нужны равнодоступные отказ и отзыв выбора, а не только кнопка «Понятно».
Обновите раздел cookie до подключения таких сервисов.

Правовые ориентиры, проверенные 18.09.2026:

- [152-ФЗ, статья 18.1: доступ к политике](https://www.consultant.ru/document/cons_doc_LAW_61801/eeeebe22bf738fd65bb66b95cc278911ae2525ee/).
- [152-ФЗ, статья 9: отдельное согласие и доказательство его получения](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/).
- [152-ФЗ, статья 6: основания обработки](https://www.consultant.ru/document/cons_doc_LAW_61801/315f051396c88f1e4f827ba3f2ae313d999a1873/).

Основной домен `vosem-utra.ru` к этой демоверсии не подключается.

Это публичная демоверсия, не закрытая ссылка: сайт, исходники и история
репозитория доступны всем. Запрет `noindex, nofollow` на страницах
просит поисковые системы не индексировать предпросмотр, но не ограничивает
доступ. Для основного домена используйте `npm run build:hosting` — этот режим
включает индексацию главной автоматически. Исходники предпросмотра не меняйте.

Форма остаётся в режиме `data-preview="true"`: отправки анкет, сервера регистрации
и загрузки reCAPTCHA нет. Перед публикацией проверяйте `npm test` и
`npm run build`. Не добавляйте секреты, `.env`, базы, логи или выгрузки гостей.

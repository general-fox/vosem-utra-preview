# Восемь утра — демоверсия

Рабочая папка этой версии: `C:\vosem-utra\github-preview`.

## Локальный запуск

Требуется Node.js с npm. При первом запуске: `npm install`.

```powershell
cd C:\vosem-utra\github-preview
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173/).
Сохранённые изменения автоматически отображаются в браузере.
Остановить сервер: Ctrl+C.

`npm run build` собирает все четыре страницы в `dist`.
`npm run preview` позволяет посмотреть эту сборку локально.
Относительные пути подходят для размещения сайта в подпапке GitHub Pages.
Также страницы работают как обычные статические файлы из корня репозитория.

## Что редактировать

- `index.html` — главная страница и тексты.
- `style.css` — фирменные цвета, общие компоненты, главная и мобильная версия.
- `registration.html`, `registration.css` — страница клуба гостей.
- `registration.js` — маска телефона и логика формы.
- `privacy.html`, `consent.html`, `legal.css` — правовые документы и их оформление.
- `site.js` — мобильная навигация и согласованное появление текста, фотографий,
  карточек и декоративных блоков. Цели отмечены `data-reveal` в HTML.
  Начальное состояние задаётся до первой отрисовки: нет вспышки «видно → скрыто».
  Появление запускается один раз при входе в экран, задержки внутри группы
  не превышают 180 мс. Фотографии декодируются перед появлением карточки.
  Если основной скрипт не загрузился, предохранитель открывает содержимое
  через 2,3 секунды. Фокус, якорные ссылки и возврат из истории не ждут анимации.
  Анимации отключаются при настройке «Уменьшение движения»; без JavaScript
  всё содержимое остаётся видимым. Поля формы не анимируются.

Декоративные звёздочки и солнца — встроенные SVG, не текстовые символы:
на iOS они не заменяются цветными эмодзи. Шторка — заранее отрисованный слой
с фирменным SVG-узором и неглубоким изогнутым краем (на мобильном ещё мягче).
Web Animations API поднимает весь слой за 1,1 секунды, меняя только transform:
без покадрового пересчёта SVG, размытия и дополнительных библиотек.
Высота закреплена через lvh, чтобы адресная строка телефона не меняла геометрию
во время подъёма. При недоступной анимации сайт открывается сразу.
Обычный свайп начинает подъём, но не обрывает его; ссылки, поля
и клавиатурный фокус доступны сразу. На мобильном ход параллакса ограничен
примерно 14–25 пикселями в каждую сторону, с разной инерцией трёх карточек.

GitHub Pages не исполняет PHP. В этой копии форма явно помечена
`data-preview="true"`, кнопка отключена, обработчик не отправляет данные.
Для настоящей регистрации потребуется серверная версия из `../site`.
Изменения этой демоверсии не синхронизируются в `../site` автоматически.

палитра со стр. 14–19, Lato со стр. 20, лучи и композиционные принципы

Прежние `assets/brand-pastry.jpg` и `assets/brand-breakfast.jpg` извлечены из изображений
на страницах 28 и 30 PDF соответственно. В трёх карточках теперь стоят
предоставленные заказчиком фотографии кофе с меню, завтрака с тостом и сырников к чаю. Для кофе с помощью
встроенного ImageGen расширено окружение кадра; исходное фото сохранено отдельно.
Фото завтрака и сырников не перерисованы. Для браузера подготовлены WebP в двух разрешениях,
без увеличения исходных пиксельных размеров и с качеством 92. В блоке о кофейне
осталась одна иллюстрация бариста: WebP сделаны из PNG 972 × 1280, а не старой
уменьшенной копии. Подробности и промпты: [подготовка фотографий](docs/photo-preparation.md).
Остальные изображения и шрифты взяты из существующего сайта; исходные PNG сохранены.
Иллюстрации интерьера не являются фотографиями.
Цены и часы работы из демонстрационных макетов брендбука не переносились.

### Обновлённая вывеска

`assets/cafe-sign-enhanced.png` — улучшенная встроенным ImageGen версия
исходного `assets/cafe-sign.png` (исходник сохранён без изменений).
Готовое изображение: 1254 × 1254. Для сайта используются WebP-версии
`assets/cafe-sign-enhanced.webp` и `assets/cafe-sign-enhanced-720.webp`;
браузер выбирает размер с учётом экрана. Это AI-обработка существующей
иллюстрации, а не документальная фотография фасада.

Промпт обработки (встроенный инструмент, без API/CLI):

> Use case: precise-object-edit. Asset type: high-resolution cafe website contact-section image. Image 1 is the edit target, not a style reference. Enhance the existing image only: restore crisp, natural detail, remove softness and compression, render at a high resolution suitable for retina displays (approximately 2048 x 2048). Preserve the exact square crop, perspective, lightbox shape and position, dark frame, red-brown brick facade, window edges, warm understated illumination and original atmosphere. Preserve the brand wordmark exactly as shown, including its particular elegant black serif letterforms; text verbatim in Cyrillic: "Восемь утра". No text replacement, no extra letters, no new objects, no redesigned architecture. Refine brick texture and frame edges gently without oversharpening or halos. Do not change the scene or add artistic stylization. Output only the enhanced existing image, not a comparison or a mockup.

### Перед включением настоящей регистрации

Это оформление интерфейса, а не подтверждение юридической готовности сервиса.
Оператору/юристу нужно согласовать тексты и фактические процессы: состав данных,
цели и сроки, хостинг и журналы сервера, CRM/программа лояльности, получатели,
локализация баз данных и необходимость уведомлений Роскомнадзора.
Факт получения согласия и его версию необходимо фиксировать на сервере;
сервер должен отклонять анкету без согласия. В демоверсии backend отсутствует.

В `registration.js` сохранена неактивная логика Google reCAPTCHA из серверного
сайта. Сейчас она не загружается благодаря `data-preview="true"`. Нельзя просто
включить её без отдельной проверки передачи данных и cookie. После выбора
хостинга нужно проверить его заголовки Set-Cookie и фактические запросы сайта.
При добавлении необязательной аналитики/рекламных сервисов, работающих на
основании согласия, их загрузка должна происходить только после явного выбора;
нужны равнодоступные отказ и отзыв выбора, а не только кнопка «Понятно».
Обновите раздел cookie до подключения таких сервисов.

Правовые ориентиры, проверенные 18.09.2026:

- [152-ФЗ, статья 18.1: доступ к политике](https://www.consultant.ru/document/cons_doc_LAW_61801/eeeebe22bf738fd65bb66b95cc278911ae2525ee/).
- [152-ФЗ, статья 9: отдельное согласие и доказательство его получения](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/).
- [152-ФЗ, статья 6: основания обработки](https://www.consultant.ru/document/cons_doc_LAW_61801/315f051396c88f1e4f827ba3f2ae313d999a1873/).

## Публикация предпросмотра для заказчика

Репозиторий: https://github.com/general-fox/vosem-utra-preview

Адрес GitHub Pages после включения публикации:
https://general-fox.github.io/vosem-utra-preview/

Настройки Pages: **Deploy from a branch → main → / (root)**.
В корне уже есть `.nojekyll`; все четыре HTML-страницы работают без сборки,
а относительные ссылки поддерживают подпапку `/vosem-utra-preview/`.
Следующий push в `main` автоматически обновляет предпросмотр.
Основной домен `vosem-utra.ru` к этой демоверсии не подключается.

Это публичная демоверсия, не закрытая ссылка: сайт, исходники и история
репозитория доступны всем. Запрет `noindex, nofollow` на четырёх страницах
просит поисковые системы не индексировать предпросмотр, но не ограничивает
доступ. При переносе на основной домен для запуска SEO его нужно убрать.

Форма остаётся в режиме `data-preview="true"`: отправки анкет, серверной части
и загрузки reCAPTCHA нет. Перед публикацией проверяйте `npm test` и
`npm run build`. Не добавляйте секреты, `.env`, базы, логи или выгрузки гостей.

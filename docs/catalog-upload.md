# Сайт без доставки — обновление для REG.RU

В этой версии работают меню, фотографии, группы, ручное добавление блюд,
защищённая админка и существующая форма клуба гостей. Корзина, оформление
самовывоза и доставки, КДС и приложение сотрудников отключены.

Обычная сборка также не включает подтверждение номера звонком. Файлы модуля
uCaller и его интерфейс не попадают в неё; серверный флаг сборки блокирует
подключение даже при наличии старого `ucaller-config.json` или
`loyalty-phone-policy.php`. Регистрация использует действующие настройки
FlexBonus и reCAPTCHA. Тестирование звонков остаётся отдельной командой
`npm run build:reg:test:ucaller` и отдельным доменом test888.ru.

Для первого переноса с test888.ru на vosem-utra.ru используйте также
`PRODUCTION-MIGRATION.md`: обычный архив кода не содержит актуальных аккаунтов,
меню или загруженных в админке фотографий.

## Как загрузить

1. Сделайте резервную копию папки сайта и соседней `vosem-utra-private`.
2. Распакуйте архив на компьютере. Содержимое `site` загрузите в корень нужного
   сайта с заменой одноимённых файлов. Для основного сайта это папка домена
   `vosem-utra.ru`, для тестового — `/www/test888.ru`.
3. Содержимое `vosem-utra-private` загрузите в существующую одноимённую папку
   рядом с папкой сайта. В ней обязательно замените `app`, включая `features.php`
   и `deployment.php`, и файлы фоновых заданий из комплекта.
4. Загрузите также скрытые `.htaccess` и `.user.ini`. В корне сайта должен находиться `app.php`,
   без дополнительной вложенной папки `site`.
5. Откройте сайт и `/admin`, обновите страницу через Ctrl+F5. В админке выберите
   группу, нажмите «Добавить блюдо», заполните название, цену, описание и фото.

Чтобы временно убрать блюдо из публичного меню, нажмите «Скрыть с сайта» на его
карточке или выключите «Показывать на сайте» в редакторе и сохраните. Блюдо останется
в той же группе в админке с пометкой «Скрыто с сайта». Кнопка «Показать на сайте»
вернёт его в меню с прежними фотографией, описанием и ценой.

Не удаляйте папки целиком. Архив не содержит и не заменяет `admin-config.php`,
`admin-data`, пароли, привязки второго фактора, загруженные фотографии, настройки
регистрации, старые заказы или ключи интеграций. Вход — с прежней почтой и паролем,
без Яндекс ID, QR-кода и подтверждения через приложение. Старые привязки не используются.
Если на этом хостинге админка ещё не настраивалась, её закрытый файл доступа
переносится отдельно; пароль в публичную папку сайта помещать нельзя.

Архив с названием `vosem-utra` предназначен для основного домена и сохраняет SEO.
Архив с названием `test888` предназначен только для теста и закрыт от индексации.
Не смешивайте их папки `app`. PHP: 8.3+ с PDO SQLite, OpenSSL, fileinfo и GD.

Фотографии JPG, PNG и WebP можно выбирать размером до 100 МБ. Большие исходники
админка пропорционально уменьшает до 2400 пикселей по длинной стороне и подготавливает
для сайта перед загрузкой. Исходный файл на компьютере не изменяется.
В сборку входит `.user.ini`: `upload_max_filesize=100M`, `post_max_size=110M`,
`memory_limit=512M`. Если хостинг не применяет `.user.ini`, укажите эти значения
в настройках PHP для домена. PHP может кешировать настройки до пяти минут.
Если сервер возвращает HTTP 413 до обработки запроса PHP, попросите поддержку
хостинга поднять ограничение размера запроса веб-сервера до 110 МБ.

Вход поддерживает «Забыли пароль?» с кодом по почте. Для отправки один раз
настройте закрытый `password-reset-mail.json` и задание `auth-mail-worker.php`
по инструкции `PASSWORD-RECOVERY.md` в архиве. Без этой настройки письма не
отправляются; обычный вход продолжает работать с прежними данными.

## Что происходит со старой доставкой

Старые ссылки оформления и API заказов возвращают 404. Старые настройки КДС
не включают модуль обратно. Вместо ранее установленных cron-обработчиков
архив содержит безопасные заглушки: они завершаются без отправки данных.
Старые файлы и история на хостинге могут оставаться, но модуль ими не пользуется.
Тестовые позиции КДС не выводятся в публичном меню. Карточки и история не удаляются.

Ранее опубликованные обычные блюда остаются на сайте. После загрузки проверьте
их фотографии, цены и группы, затем сохраните пробное блюдо и убедитесь,
что оно появилось на главной. Проверка регистрации проводится по её действующим
настройкам хостинга: рабочие ключи в этот архив не включены.

Код модуля доставки сохранён в исходном проекте. Порядок повторного подключения
описан в `modules/delivery/README.md`; простого изменения клиентского HTML
недостаточно для включения отправки заказов.

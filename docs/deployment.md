# Один проект, три способа просмотра

Все изменения кода выполняются в `C:\Websites\vosem-utra\github-preview`, в существующем
репозитории `general-fox/vosem-utra-preview`. Отдельной рабочей копии `../site`
больше нет. Прежние материалы сохранены в локальном архиве вне репозитория.

| Где | Как запускается | Какие данные |
| --- | --- | --- |
| Локально | `npm run dev`: Vite + PHP | `.data/php-runtime/`, приватно на компьютере |
| GitHub Pages | Существующая публикация `main / (root)` | Статические страницы и `public/data/menu.json`, без серверного входа |
| REG.RU | PHP-сборка `npm run build:reg` | Приватное хранилище на хостинге, вне публичной папки домена |

## Повседневная работа

1. Открыть существующий `vosem-utra-preview` в GitHub Desktop.
2. Запустить `npm run dev` из `github-preview`, внести и проверить правки.
3. Проверить состав изменений, Commit и Push origin — для обновления GitHub.
4. После согласования собрать `npm run build:reg`, выполнить `npm run test:reg`
   и загрузить комплект по [инструкции REG.RU](reg-upload.md).

`npm run build` создаёт статическую версию `dist/` для предпросмотра.
`npm run build:hosting` создаёт промежуточную `dist-hosting/`.
На REG.RU нужен именно полный `dist-reg/`, а не промежуточный каталог и не весь Git-репозиторий.

## Не перепутать код и рабочие данные

Меню, аккаунты и фото, добавленные через локальную админку, находятся в
`.data/php-runtime/`. Git намеренно их не публикует. Начальный каталог
`public/data/menu.json` используется для новой установки и статического просмотра;
сборка не заменяет им уже сохранённое меню.

При первом переносе применяйте защищённый экспорт и восстановление:
[единая серверная часть и перенос данных](local-runtime-and-transfer.md).
Если на сервере уже есть данные, сначала резервная копия и выбор основной версии;
не восстанавливайте старое локальное хранилище поверх рабочего сервера.

При обычном обновлении заменяются только код и необходимые версии правовых
документов. Пароли, TOTP, меню, заказы, согласия и ключи интеграций сохраняются.
Публикация в GitHub не выполняет перенос данных и не обновляет REG.RU.

## Что больше не нужно делать

- Не запускать сайт из старых `site/`, `hosting-live-check/` или `reg-ru-package/`.
- Не редактировать `dist*`: это результат сборки, изменения будут потеряны при следующей сборке.
- Не запускать Node-сервер на REG.RU: текущая серверная часть работает на PHP.
- Не помещать `.data`, `.env`, архивы, ключи или приватную папку хостинга в GitHub.

Подробности индексирования основного домена: [SEO](seo.md).
Архив старых инструкций оставлен вне репозитория только для восстановления,
а не как действующий порядок размещения.

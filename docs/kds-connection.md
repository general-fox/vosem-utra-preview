## Что работает

PHP сайта получает сервисный токен и передаёт новый заказ в КДС. До принятия
сайт читает get-pending-order по Pending ID. После Accepted проверяет кассовый
заказ через get-order по externalGuid. Создание для проверки не повторяется.
Состояние хранится в SQLite и переживает перезапуск PHP.

Новая заявка сайта и задача отправки сохраняются одной транзакцией.
Перед единственным POST в КДС на диск записывается отметка отправки.
Потеря ответа без Pending ID означает неизвестный результат: повторный POST
запрещён, нужна сверка с сотрудником КДС. Отсутствие ответа сети не считается
доказательством отсутствия заявки. Ответ 404 при проверке известного ID
показывается отдельно. Старые сохранённые заявки автоматически не отправляются.

Состояние проверяет открытая страница заказа и фоновое задание cron.
Ссылка checkout.html#order=… восстанавливает экран после обновления в том же
браузере. Одного ID недостаточно для доступа: нужен HttpOnly cookie владельца,
действующий 8 часов. Обновление требует CSRF и правильного Origin.

## Меню и расчёты

Для проверки добавлены две отдельные позиции без подмены меню кофейни:

| ID сайта | ID КДС | Блюдо | Цена |
|---|---|---|---|
| kds-test-porridge | 1012080 | Пшенная каша с тыквой | 200 ₽ |
| kds-test-syrniki | 1013259 | Сырники с малиновым вареньем и сметаной | 395 ₽ |

Они добавляются в существующее меню при первом открытии, сохраняя остальные
позиции и изменения админа. На стенде заказать можно только эти два ID.
Пока они перечислены в testItems, удалённая тестовая позиция добавится снова;
для временного скрытия снимите её публикацию в админке.

Перед отправкой проверяются актуальные цены КДС, валюта предоплаты, стоп-лист
и остатки. Цена должна совпасть с подтверждённой на сайте. Количество создания
передаётся в порциях, остатки проверяются в тысячных порции.
Блюда с обязательными модификаторами или отдельными периодами доступности
блокируются: их настройка не входит в проверку этих двух простых блюд.

Имя и телефон идут в поля клиента; самовывоз/доставка, адрес со всеми заполненными
деталями, время и пожелания — в комментарий. Для автоматической маршрутизации
доставки в кассе этого недостаточно: отдельные поля/настройки нужно согласовать
при подключении рабочего меню. Положительная плата доставки пока блокируется;
неизвестная стоимость не заменяется нулём на сайте и не включается в предоплату.

## Оплата и окружение

API поддерживает предоплату. На тестовой точке записывается **условная предоплата**
в валюте организации «Оплата Приложение Stars» (1043900).
Запросы в банк и pay-order не выполняются. Каждый комментарий содержит «ТЕСТ»,
«НЕ ГОТОВИТЬ» и пояснение об отсутствии банковской оплаты.
Такой режим нельзя включить на рабочем сайте: проверки требуют staging,
noindex и конкретную согласованную организацию.

Для рабочего запуска потребуются реальная схема оплаты либо поддержка
неоплаченного заказа со стороны КДС, рабочее меню и HTTPS API.

## Настройки и обновление

Доступ хранится в `vosem-utra-private/kds-config.json` вне публичного каталога.
Он не входит в Git, браузерные JS/HTML или обычную сборку.
enabled и enableTestOrders включаются явно; menuMap задаёт соответствия ID.
testItems содержит отдельные карточки для теста. Пример без секретов находится
в hosting/kds-config.example.json.

По согласованию для временного теста разрешён только точный HTTP API
http://89.108.109.59:5262/api/v1 и указанная выше организация
с allowHttpForTest=true. HTTP не шифрует сервисный доступ и данные.
Перед рабочим запуском нужны HTTPS и замена тестового пароля.
Перенаправления API запрещены, HTTPS-сертификаты проверяются.
В ошибки и логи не выводятся пароль, токен или тела ответов КДС.

Обновление устанавливается поверх стенда с сохранением admin-config.php,
admin-data, orders-config.php, orders-data. В отдельном приватном комплекте
передаётся заполненный kds-config.json; его и весь архив нельзя публиковать.

## Фоновая проверка

В планировщике ispmanager добавьте запуск каждую минуту. Выберите PHP 8.3+
с cURL, PDO SQLite, OpenSSL, fileinfo и GD, память 256 МБ или больше.
Команда содержит абсолютные пути именно вашего аккаунта:

```text
<путь к PHP> <путь к vosem-utra-private>/kds-worker.php --private-dir=<путь к vosem-utra-private>
```

Это одноразовая настройка в панели, запускать терминал для каждого заказа не нужно.
Worker работает только из CLI, перекрывающиеся запуски защищены блокировкой.
Без cron сайт проверяет статус, пока открыта страница заказа; после закрытия
вкладки обработку продолжает cron. Не включайте старый Telegram worker на стенде.

Диагностика для разработчика, без создания заказа:

```text
php hosting/kds-check.php --config=.data/kds-connection/kds-config.json
```

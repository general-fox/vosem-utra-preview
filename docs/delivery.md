# Корзина и оформление: текущий этап

Основание — `docs/delivery-site-spec.md`. Реализована гостевая часть и PHP API
сохранения заявки. По `docs/delivery-staff-spec.md` добавлены бот, Web App
сотрудников и принятие заказа. Подключение описано в [telegram.md](telegram.md).
Интегратор r_keeper и онлайн-оплата ещё не подключены. Локальные проверки
используют подменённый транспорт Telegram и не заменяют приёмку HTTPS-стенда.

## Где что работает

| Среда | Возможности |
| --- | --- |
| `npm run dev`, `npm run preview` | Интерфейс, меню и админка; заказы обрабатывает локальный PHP, только тестовые данные |
| GitHub Pages, `dist/` | Меню, корзина и демонстрация оформления; API отсутствует, заказ не считается отправленным |
| REG.RU, `dist-reg/` | PHP, приватная SQLite, актуальный каталог; приём выключен до согласования настроек |
| `npm start` | Тот же единый локальный PHP, что и `npm run dev` |
| `npm run legacy:start` | Прежний Node-сервер для диагностики; не текущая рабочая версия |

Локальный PHP находится через `PHP_BIN`, соседний `.tools/php/php.exe` на Windows
или `php` в PATH. Нужны OpenSSL, GD и PDO SQLite. Vite запускает отдельный процесс при
обращении к API; доступ к нему ограничен loopback и случайным служебным
ключом. При остановке Vite процесс закрывается. Тестовая база хранится в
`.data/php-runtime/orders-data/orders.sqlite`, рабочее меню — в
`.data/php-runtime/admin-data/menu.json`. Админка, гостевые заказы и API сотрудников
используют единый PHP. Прежняя `.data/orders-development/` сохраняется как старая
тестовая копия и автоматически не объединяется с новой базой.
Первый запуск переносит локальные аккаунты, меню и фото; подробнее —
[единый PHP и перенос](local-runtime-and-transfer.md). Тестовое расписание круглосуточное, подготовка
30/60 минут, горизонт 7 дней; эти значения не являются условиями кофейни.

## Данные и API

- `availableForOrder` независимо от `published`. Старые записи без поля доступны
  по умолчанию, скрытые и недоступные позиции сервер заказать не разрешает.
- `GET /api/menu` — опубликованные позиции и `revision` одной версии каталога.
- `GET /api/ordering` — доступность оформления, условия, слоты в часовом поясе
  кафе и CSRF-токен. Гостевая HttpOnly cookie имеет SameSite=Strict и Secure на HTTPS.
- `POST /api/orders/quote` — серверная сумма в целых копейках RUB, случайный
  `quoteId`, срок 5 минут. Неизвестная доставка и итог равны `null`, самовывоз — 0.
- `POST /api/orders` — та же заявка плюс `quoteId` и `idempotencyKey`.
  Транзакция сохраняет заявку, исходный снимок, историю и ожидающее уведомление.
  `201` означает сохранение; `200` — повтор прежнего сохранённого запроса.
  Изменённый запрос с прежним ключом получает `409`; новый расчёт требует
  отдельного подтверждения. Доступа по публичному номеру заказа нет.

Изменяющие запросы требуют `application/json`, корректный Origin, гостевую cookie
и `X-CSRF-Token`. Лимиты частоты сохраняются в SQLite; размер запроса ограничен
32 КБ. Поля, количество, цены, наличие и расписание проверяются сервером.
Источником денег служит только актуальное меню. Создание и повторы защищены
транзакцией и уникальными ключами; заказ сначала сохраняется, затем можно
обрабатывать уведомление. При настроенном боте очередь обрабатывает приватный
`telegram-worker.php` из cron; без подключения уведомления ожидают настройки.

Браузер сохраняет только `{id, qty}`. Телефон, адрес, форма и ключ повтора живут
в памяти вкладки. После неопределённого ответа повторяется прежнее тело и ключ,
форма блокируется до выяснения результата. Обновление/закрытие вкладки прерывает
эту возможность восстановления: интерфейс предупреждает об этом. Постоянная
страница отслеживания в этот этап не входит.

Основной вариант — сайт и API на одном домене. `API_BASE_URL` оставлен явной
настройкой клиента, но междоменные cookies/CORS на PHP сейчас не включены.
Нельзя просто указать сторонний сервер и считать такую схему проверенной;
для отдельного API потребуется согласованная настройка CORS, CSP и сессий.

## Условия перед настоящим запуском

`hosting/orders-config.example.php` не содержит действующих условий или ключей.
Приватный `orders-config.php` сохраняется при обновлении. Производственный
режим требует `enabled=true`, `termsApproved=true`, полного валидного расписания,
тарифов/явного режима уточнения доставки по телефону, лимитов и утверждённого
документа согласия. Страница `order-terms.html` пока содержит только инструкцию
для теста. Платёжные реквизиты и банковские данные сайт не запрашивает.

Перед запуском нужны: утверждение условий кафе; HTTPS-стенд с закрытым доступом
и отдельной базой; подключение и проверка бота/экрана сотрудников; процесс обработки
ожидающих заявок и ошибок уведомления; сроки хранения и резервное копирование;
приёмка всего сценария для конкретного Git commit SHA и HTTPS-адреса.

## Проверки и GitHub

```powershell
npm test
npm run build
npm run build:reg
npm run test:reg
```

GitHub Actions `.github/workflows/checks.yml` повторяет эти проверки на push/PR.
Он не публикует сайт и не открывает репозиторий. Для существующего GitHub Pages
используются `main → / (root)`; `dist/` — отдельная статическая сборка для проверки.
После одобрения демонстрации PHP-пакет загружается на отдельный HTTPS-стенд.
Не добавлять `.env`, `.data`, `orders-config.php`, `orders-data/`, SQLite,
резервные копии и реальные заявки в Git или архив с исходниками.

На HTTPS-стенде проверить мобильный экран, редактирование меню, повтор после
потери ответа, изменение цены/наличия между расчётом и отправкой, доставку с
неизвестной стоимостью, закрытые часы, слишком ранние слоты и невозможность
скачать базу. Номер заказа не означает принятие или оплату.

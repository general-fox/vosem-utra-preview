# Группы меню сайта и кассы

Переключатель «На сайте / На кассе» открывает два представления одного каталога. Новые блюда добавляются только через импорт из базы кассы: создание вручную закрыто и в интерфейсе, и в API.

## Группы сайта

Группы сайта одноуровневые и создаются вручную. В окне «Редактировать группы» можно добавить, удалить группу и изменить порядок списка. Перетащите группу вверх или вниз за ручку; для клавиатуры и телефона доступны кнопки перемещения. После «Сохранить группы» сайт покажет группы в порядке сверху вниз. «Отмена» отменяет несохранённые изменения.

При открытии редактора сохранённый список загружается автоматически. Если меню изменится во время редактирования или сервер не подтвердит сохранение, появится предупреждение с предложением закрыть и снова открыть редактор. Перед закрытием несохранённого черновика требуется подтверждение; повторное открытие показывает актуальные данные.

При удалении непустой группы выберите, куда перенести блюда. Для группы, состоящей только из импортированных блюд, доступно снятие всех этих блюд с сайта: они сохранятся в разделе «На кассе». Старые блюда без привязки к источнику необходимо перенести в другую группу. Удаление группы не удаляет блюда из базы кассы.

Старые вложенные группы сайта при обновлении становятся самостоятельными группами. Названия и привязки блюд сохраняются; перед миграцией сервер сохраняет закрытую резервную копию меню.

## Размещение блюда

В разделе «На кассе» сохраняется исходная вложенность r_keeper. Карточки групп открывают следующий уровень; рядом могут находиться блюда. Поиск работает внутри выбранной ветки.

Откройте блюдо и выберите «Группа на сайте». После сохранения оно появится на сайте. Например, кофе из кассовой группы «Бар / Кофе» можно разместить в группе сайта «Напитки». Чтобы снять импортированное блюдо с сайта, выберите «Не размещать на сайте» либо используйте «Убрать с сайта» на его карточке.

В редакторе нет ручного порядка блюда и флажков публикации или доступности заказа. Название, описание, цену и фотографию можно редактировать для сайта. Правки не отправляются обратно в кассу. Повторный импорт сохраняет назначенную группу и правки карточки.

Существующие блюда с назначенной группой считаются размещёнными, включая ранее скрытые отдельным флажком. Тестовые импортированные блюда остаются недоступными для заказа.

## Стоп-лист и остатки

Кнопка «Синхронизировать стоп-лист и остатки» доступна в обоих разделах. Она запрашивает get-dish-rests у организации из закрытого kds-config.json. Новые блюда и группы эта кнопка не импортирует. Запрос выполняется сервером; сервисные имя, пароль и токен не попадают в браузер.

На карточках видны запрет продажи и остаток, возле кнопки — время последнего успешного обновления. Запрещённые блюда и позиции с остатком менее одной порции нельзя заказать; при положительном остатке сервер проверяет количество при расчёте и отправке заказа. API передаёт тысячные доли: 2500 соответствует 2,5 порции. Снятое кассой ограничение снимается после следующей успешной синхронизации.

При ошибке связи последние успешные данные сохраняются. Снимок относится к конкретным адресу API и организации: после смены подключения старые ограничения не применяются к новой точке. Синхронизация ручная; актуальная повторная проверка КДС перед отправкой заказа остаётся включённой.

Снимок хранится вне сайта в kds-data/menu-availability.json. Для синхронизации нужны действующее подключение и доступ сервера сайта к КДС. Сообщение «Подключение к кассе не настроено» означает, что сначала нужно завершить настройку закрытого файла. Можно настроить подключение только для чтения, оставив enableTestOrders: false.

## Технический контракт

categories — одноуровневые ручные группы сайта, sourceCategories — исходное дерево кассы. items[].category — группа сайта или null для неразмещённого импортированного блюда. source с идентификаторами источника изменяется только доверенным импортом. Публикация определяется назначением группы, фактическая доступность заказа дополнительно ограничивается сервером и кассой.

POST /api/admin/sync-availability защищён сессией, Origin и CSRF; перед записью после сетевого запроса сессия проверяется повторно. Ответ содержит каталог с вычисляемыми keeperSync и items[].keeperAvailability; эти поля не принимаются как редактируемые настройки. Сохранение групп и блюд остаётся атомарным с проверкой версии меню.

Ранее загруженная тестовая группа REDBOX остаётся в дереве кассы. Переключение подключения не импортирует новое меню и не переносит идентификаторы старых блюд в другую организацию. Актуальные адреса и объект нового стенда описаны в [настройке КДС](kds-connection.md).

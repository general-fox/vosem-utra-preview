# Восстановление пароля администратора

На странице входа нажмите «Забыли пароль?», укажите почту администратора,
введите восемь цифр из письма и задайте новый пароль. После этого войдите обычным
способом: почта и новый пароль. Подтверждение через приложение отключено.
Старые сеансы и запомненные устройства этого пользователя отзываются.

Если письмо уже пришло, укажите почту и нажмите «Уже есть код». Это открывает ввод
кода без нового письма, в том числе во время ограничения отправки и в новой вкладке.
Код действует 10 минут с момента запроса, ожидание нового письма его не продлевает.

Восстановление работает только для существующей записи администратора. Оно не
создаёт аккаунты и не даёт доступ участникам клуба гостей. Если запись удалена
на хостинге, сначала нужно восстановить её из резервной копии.

## Однократная настройка на test888.ru

1. Загрузите обновление сайта и приватной папки из архива. Не заменяйте
   `admin-config.php` или `admin-data`: там действующие аккаунты и фотографии.
2. В Яндекс ID ящика `v.utra@yandex.ru` создайте отдельный пароль приложения
   для Почты. В настройках почтовых программ включите разрешённый доступ
   с паролями приложений по [инструкции Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).
3. Заполните только `password` в закрытом `password-reset-mail.json`.
   Пример есть в архиве под именем `password-reset-mail.example.json`.
   Это пароль приложения, не основной пароль Яндекса.
4. Загрузите заполненный `password-reset-mail.json` в `/www/vosem-utra-private/`,
   рядом с `admin-config.php`, **вне** `/www/test888.ru/`. Файл не публикуется в GitHub.
5. В REG.RU → «Планировщик» создайте отдельное задание: каждую минуту (все пять
   полей `*`). Команда для текущего тестового хостинга:

   ```text
   /opt/php/8.3/bin/php /var/www/u3665046/data/www/vosem-utra-private/auth-mail-worker.php
   ```

   Это постоянное задание отправки писем; не удаляйте его после первого запуска.
   Доставку и КДС оно не включает. Повторный запуск одновременно с предыдущим
   не создаёт второй отправитель.
6. На `https://test888.ru/admin` запросите код на свою почту. Письмо обычно
   отправляется в течение минуты. Проверьте входящие и спам. Код действует
   десять минут с запроса, затем нужно запросить новый.

Однократная настройка на хостинге клиента такая же, но пути и пользователь REG.RU
будут другими. Для основного сайта используйте архив `vosem-utra`, для тестового —
`test888`. Файл SMTP заполняется отдельно и не входит в общие архивы.

## Что проверено в коде

- Случайный восьмизначный код, 10 минут, не более пяти проверок; после успешной
  проверки код больше не действует. На ввод нового пароля отводится ещё 5 минут.
- Повторное письмо не раньше 60 секунд. Часового ограничения нет. Для восстановления
  окна ограничений по IP, адресу и всему серверу — максимум 3 минуты; отклонённые
  запросы не продлевают эти окна. Старые часовые и 15-минутные ограничения
  восстановления сокращаются при первом запросе после обновления. Защита обычного
  входа не меняется.
- Кнопки учитывают `Retry-After` сервера и показывают оставшееся время ожидания.
  Ограничение отправки писем не блокирует проверку действующего кода. Отклонённый
  ранний запрос не расходует дополнительную квоту отправки по IP и всему серверу.
- При обновлении той же вкладки или возвращении из почты сохраняется шаг ввода
  кода: в `sessionStorage` хранятся почта, сроки и идентификатор запроса, если он есть.
  Введённые коды, новый пароль и разрешение на его смену не сохраняются.
  Идентификатор без кода не даёт доступа; сервер проверяет срок и число попыток.
- Существующая и неизвестная почта получают одинаковый ответ. Сеть SMTP не
  участвует в HTTP-запросе; письма отправляет отдельный процесс.
- В состоянии аккаунта хранится HMAC кода с солью запроса. Ввод по почте использует
  общее ограничение в пять проверок за три минуты для адреса, независимо от вкладки
  и IP; пять ошибок также исчерпывают сам код. Одна успешная проверка погашает все
  ожидающие коды этой почты. Ранее выданные коды старого формата принимаются только
  со своим исходным идентификатором запроса, пока не истёк срок.
- До отправки письмо находится в
  зашифрованной AES-GCM очереди вне публичной папки. После отправки/истечения
  срока письмо удаляется. Неотправленные письма повторяются до трёх раз.
- SMTP через TLS с проверкой сертификата, PHPMailer 7.1.1. Ошибки SMTP, пароли,
  коды и токены не выводятся посетителю или в журнал заданий.
- После смены пароля приходит уведомление. Восстановление не создаёт авторизованный
  сеанс: для входа нужно указать почту и новый пароль.

Файлы настроек и серверные данные не заменяются сборкой. Приватную настройку
SMTP сохраняйте отдельно при резервном копировании хостинга; перенос локальной
админки сам по себе её не переносит. Содержимое временной почтовой очереди
переносить между стендами не нужно.

## Если письмо не приходит

После запуска планировщик сохраняет безопасный отчёт
`/www/vosem-utra-private/auth-mail-status.json`. В нём есть время запуска,
счётчики и обозначение ошибки без адресов получателей, паролей и кодов.
Если файл отсутствует или время не обновляется, проверьте выполнение задания.
`smtp_authentication` означает отказ в почтовой авторизации, `smtp_connection` —
проблему соединения, `smtp_tls` — проверку защищённого соединения.
`lastFailure` хранит предыдущую ошибку; актуальный результат — в `status` и `checkedAt`.

Убедитесь, что аккаунт с этой почтой существует, задание включено, пароль приложения
заполнен и SMTP-доступ разрешён в Яндексе. Вывод задания содержит только счётчики
`sent`, `failed`, `expired`. `sent` означает, что SMTP принял письмо; фактическое
попадание во входящие проверяется в почте. При `failed` проверьте пароль приложения,
доступ хостинга к `smtp.yandex.ru:465` и актуальность корневых сертификатов PHP.
Не отключайте проверку TLS для исправления соединения.

Основа проверок безопасности: [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).

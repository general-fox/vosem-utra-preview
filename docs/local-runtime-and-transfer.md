# Одна серверная часть локально и на REG.RU

Актуальная схема с 29 сентября 2026: админка, меню и заказы используют одни и те
же PHP-классы из `hosting/php/`. Vite отвечает только за удобную разработку страниц.
Публичный GitHub содержит код и исходный каталог, но не рабочие данные.

## Локальный запуск

Нужны Node.js 24+, npm и PHP 8.3+ с OpenSSL, GD, PDO SQLite. Для формы клуба на
хостинге также нужен cURL. При необходимости укажите пути `PHP_BIN` и `PHPRC`
в приватном `.env.local` (пример переменных — `.env.example`).

Запуск: `npm run dev`. Перед ним автоматически выполняется `local:prepare`.
Существующее PHP-хранилище никогда не заменяется. При первом переходе со старого
Node-варианта сохраняется копия в `.data/legacy-backups/`, затем переносятся
меню, загруженные фото и все аккаунты. Старые файлы не удаляются.

Для уже настроенного Node-аккаунта нужен однократный скрытый ввод текущего пароля
в терминале: старый scrypt-хеш проверяется, а PHP создаёт свой Argon2id/bcrypt-хеш
того же пароля. Сам пароль передаётся PHP только по stdin, не через командную
строку и не сохраняется в новом хранилище. Для ещё не использованного временного
пароля можно взять существующую приватную памятку — после проверки её хеша.
Неправильный пароль останавливает перенос. TOTP, оставшиеся резервные коды и
срок временного доступа сохраняются. Никакого обхода MFA нет.

Админка: `http://127.0.0.1:5173/admin.html`. Актуальные данные находятся только в
`.data/php-runtime/`: `admin-config.php`, `admin-data/`, `orders-data/`.
Запросы PHP принимаются лишь от локального сервера с его случайным служебным
ключом; доступ извне и подмена Origin/Host запрещены.

Добавление сотрудника: `npm run admin:add -- employee@example.ru`. Команда
создаёт новый аккаунт, но не заменяет существующий. Памятка первого входа
остаётся в `.data/php-runtime/admin-access-*.txt`. Передайте её адресату лично,
сохраните пароль в менеджере и затем удалите памятку вручную. QR привязывает
сам сотрудник. Основной аккаунт не появляется просто из-за наличия email в коде.

Старые `server/auth.mjs`, `server/menu-api.mjs` и инструменты `legacy:*` оставлены
для диагностики прежних копий. `npm run dev`, `npm start`, `npm run preview` и
`npm run admin:add` больше не используют их для рабочего локального входа.

## Первый перенос на REG.RU без смены паролей и QR

1. Завершить настройку нужных аккаунтов и проверить вход локально. Завершить
   редактирование меню на время окончательного переноса.
2. `npm run build:reg` — обычная сборка `dist-reg`, без паролей и рабочего хранилища.
3. `npm run private:export` — отдельный зашифрованный пакет в `.data/private-exports/`
   и отдельный ключ в `.data/transfer-keys/`. В пакете: все аккаунты, существующие
   хеши паролей, зашифрованные привязки TOTP, ключ шифрования TOTP, оставшиеся
   резервные коды, актуальное меню и загруженные фотографии. Памяток с открытыми
   паролями и тестовых заказов в нём нет. Ничего не отправляется в сеть.
4. Восстановить пакет в НОВУЮ приватную папку, указав целевой адрес:

   ```powershell
   npm run private:restore -- "C:\путь\данные.cafebackup" "C:\путь\ключ.key" "C:\новая-приватная-папка" https://vosem-utra.ru
   ```

   Либо на хостинге через SSH:

   ```sh
   php /private/app/private-data.php import /private/данные.cafebackup /private/ключ.key /private/new-private https://vosem-utra.ru
   ```

   Родительская папка должна существовать; целевая — отсутствовать. Инструмент
   проверяет шифрование, аккаунты и фотографии. Существующие папки не заменяет.
   Повреждённый пакет или неверный ключ не изменяют рабочую копию.
5. Только для ПЕРВОЙ установки загрузить восстановленные `admin-config.php` и
   `admin-data/` в `vosem-utra-private`, рядом с `app/`, вне публичного каталога.
   Если на REG.RU уже есть аккаунты/меню, НЕ заменять их: сначала сделать резервную
   копию серверных данных и отдельно согласовать, какая копия является основной.
   Автоматического объединения двух разных баз аккаунтов нет.
6. Проверить HTTPS, вход паролем и действующим кодом, все блюда и фото.
   Импорт сбрасывает сессии и запомненные браузеры: первый вход на новом домене
   требует пароль и код; после него браузер снова запоминается автоматически.
   Новая серверная запись не имеет отдельного 30-дневного срока. Технический cookie
   хранится до 400 дней и обновляется только при успешной проверке кода приложения;
   очистка данных браузера или отзыв доступа снова потребуют пароль.
   Пароли, QR и неиспользованные резервные коды менять не требуется.
7. При окончательном запуске проверить `publicOrigin`, включить `indexing => true`
   только на основном домене и отдельно настроить приём настоящих заказов.
   Импорт сам не включает заказы или индексацию. Приватные настройки FlexBonus,
   reCAPTCHA и существующие согласия сохраняются отдельно по `reg-upload.md`:
   этот инструмент переносит админку/меню/заказы, не интеграции клуба.

После переноса серверная копия становится основной. Не продолжайте независимо
использовать одни и те же резервные коды в двух копиях. Для отдельного длительного
тестового стенда лучше создать отдельные тестовые аккаунты.

## Последующие обновления

Заменять только код из `site/` и `vosem-utra-private/app/`. Не перезаписывать
`admin-config.php`, `admin-data/`, `orders-config.php`, `orders-data/`, конфиги
интеграций и согласия. Не восстанавливать старую локальную копию поверх сервера:
иначе можно потерять новые блюда, заказы или вернуть использованные резервные коды.

## Резервное копирование и восстановление

Локально: `npm run private:backup`. На сервере:

```sh
php /private/app/private-data.php export /private /safe/backup.cafebackup /separate/backup.key --include-orders
```

Аккаунты и меню читаются под блокировками. Для SQLite создаётся согласованный
снимок `VACUUM INTO` с проверкой целостности, а не копия занятого файла.
Заказы включаются только при `--include-orders`; локальная команда backup
добавляет этот флаг, команда export для первого переноса — нет.
Локальные тестовые заказы нельзя импортировать для HTTPS-сайта: инструмент
откажет, предложив экспорт без заказов. Восстановление для локальной проверки
разрешено с адресом `http://127.0.0.1:5173` в новую папку.

Пакет защищён AES-256-GCM; каждый пакет получает отдельный случайный ключ.
Ключ переносите и храните отдельно от пакета, не в общей папке/переписке.
Потеря ключа делает пакет невосстановимым. По умолчанию оба файла создаются на
этом компьютере в разных приватных папках; это не замена внешней резервной копии.
Не добавлять их в Git, публичный архив сайта или каталог домена.
После проверки восстановления сохраните внешний экземпляр в защищённом месте.

Встроенный инструмент рассчитан на суммарно до 32 МиБ загруженных файлов/БД;
при превышении откажет без перезаписи. Для больших объёмов нужен потоковый
серверный бэкап. Это резервная копия текущих данных, не расписание: автоматический
бэкап на REG.RU нужно включить отдельно. При восстановлении старого бэкапа
пере-настройте MFA и резервные коды, чтобы не вернуть ранее использованные коды.

## Проверки

`npm run test:reg` включает перенос Node → PHP, вход через Vite → PHP, защиту
Origin/Host/CSRF, сохранение сессии после перезапуска, экспорт/восстановление
аккаунтов/фото, отказ при неверном ключе/повреждении/существующей папке и SQLite.
Тесты используют временные данные, не реальные аккаунты, заказы или FlexBonus.

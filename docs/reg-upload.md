# Обновление «Восемь утра» на REG.RU

Сборка рассчитана на обычный PHP-хостинг. Node.js, npm и постоянно запущенный
процесс на хостинге не нужны. Сборка файлов выполняется на компьютере разработчика.

## Что подготовлено

- `site/` — файлы, которые размещаются в публичной папке домена.
- `vosem-utra-private/app/` — код админки и шаблоны, рядом с публичной папкой.
- `vosem-utra-private/legal-versions/` — предыдущие и текущая версии документов; текущая редакция автоматически добавляется при сборке. При обновлении обязательно добавить новую папку редакции на сервер, сохранив старые: без неё форма не сможет зафиксировать согласие.
- `admin-config.example.php` — пример приватных настроек без паролей и ключей.
- `orders-config.example.php` — настройки приёма заказов; по умолчанию отключены.
- `telegram-config.example.php` — пример настроек бота и допуска сотрудников.
- `telegram-worker.php`, `telegram-setup.php` — приватные служебные скрипты бота.

Админка открывается по `/admin`, вход — почта, пароль и код приложения.
Она отсутствует в меню сайта и sitemap, её страницы отдают `noindex`.
QR подключает приложение один раз; командная строка для обычных входов не нужна.

## Порядок переноса

1. Сначала согласовать внешний вид на GitHub Pages. В существующем репозитории
   `vosem-utra-preview` используется публикация `main → / (root)`; после Commit
   и Push обновляются исходные страницы. Новый репозиторий и смена папки Pages
   не нужны. `npm run build` также создаёт отдельный статический `dist/` для
   проверки, но это не папка для REG.RU. PHP, реальные ключи и рабочие данные
   в демонстрацию не входят. `staff-demo.html` показывает вымышленные заказы.
   Настоящая админка, бот, обработка заказов и регистрация на Pages не работают.
2. На REG.RU проверить PHP 8.3 или новее, OpenSSL, GD (JPG/PNG/WebP), cURL,
   PDO SQLite, сессии и HTTPS. Для обработки фотографий рекомендуем `memory_limit` 256 МБ.
   Расширения обычно включаются в настройках PHP. Не публиковать `phpinfo()`.
3. При ПЕРВОЙ установке подготовить приватные данные через `npm run private:export`
   и восстановить их в новую папку командой `private:restore`, указав точный HTTPS
   адрес назначения. Все PHP-аккаунты, пароли, привязки телефона, оставшиеся
   резервные коды, меню и фотографии сохраняются; тестовые заказы исключены.
   Ключ пакета хранится отдельно. Пошаговая инструкция: [единый PHP и перенос](local-runtime-and-transfer.md).
   Прежний `hosting:access -- --migrate-local` предназначен только для старого Node
   runtime и заменяет пароль основного аккаунта — для нового PHP-переноса не нужен.
   Если на сервере уже есть рабочие аккаунты/меню, НЕ заменять их локальным пакетом:
   сначала резервная копия и отдельное согласование основной копии данных.
   Окончательный пакет готовится непосредственно перед переносом; затем рабочей
   становится серверная копия, чтобы не расходовать резервные коды в двух местах.
4. Собрать `npm run build:reg`. Получится каталог `dist-reg/` без секретов.
5. До замены рабочего сайта проверить этот комплект на тестовом адресе с HTTPS.
   Для тестового адреса задать его точный `publicOrigin` и `indexing => false`
   в приватном конфиге; ограничить доступ к тестовому сайту средствами хостинга.
   Сам `noindex` не ограничивает доступ посетителей.
6. Сохранить резервную копию существующих файлов сайта, `vosem-utra-private`,
   согласий, данных админки и ключа шифрования. Убедиться, что копия восстанавливается.
7. В публичную папку домена загрузить содержимое `site/`. Папка `site` внутри
   домена не создаётся. В приватную соседнюю папку загрузить `app/` и добавить
   отсутствующие версии документов. Не удалять рабочие `loyalty.php`,
   `recaptcha.php`, `consents/`, `admin-config.php`, `admin-data/`,
   `orders-config.php`, `telegram-config.php` и `orders-data/`.
   Для бота также обновить приватные `telegram-worker.php` и `telegram-setup.php`.
8. Только при первой установке отдельно добавить подготовленный
   `admin-config.php` в приватную папку и при миграции — новый `admin-data/`.
   `admin-access*.txt`, пакеты и ключи не загружаются в публичную папку. При миграции используется
   существующая запись приложения; при новой настройке владелец подтверждает
   подключение своим кодом и сохраняет резервные коды. Пароль без второго фактора
   не даёт доступа к управлению меню.
9. Оставить перенаправления HTTP → HTTPS и `www` в настройках REG.RU.
   В `.htaccess` сборки они намеренно не дублируются — сохранён принцип вашего
   исправления от 21 сентября. PHP должен получать корректный признак HTTPS;
   пользовательским `X-Forwarded-*` заголовкам приложение не доверяет.

Пример расположения:

```text
папка-аккаунта/
├── vosem-utra.ru/              # публичная папка домена
│   ├── .htaccess
│   ├── app.php
│   ├── assets/
│   └── api/register.php
└── vosem-utra-private/         # снаружи публичной папки
    ├── app/
    ├── admin-config.php
    ├── admin-data/             # создаётся PHP, не заменяется при обновлении
    ├── orders-config.php       # согласованные условия, приватный файл
    ├── telegram-config.php     # токен и список сотрудников, приватный файл
    ├── telegram-worker.php     # обработчик очереди для cron
    ├── telegram-setup.php      # разовая настройка бота
    ├── orders-data/            # SQLite заявок, не заменяется при обновлении
    ├── loyalty.php             # существующий ключ, сохранить
    ├── recaptcha.php           # существующие настройки, сохранить
    ├── consents/               # существующие согласия, сохранить
    └── legal-versions/
```

Пользователь PHP должен иметь право записи в `admin-data/`, `orders-data/` и `consents/`.
Рабочие данные, ключи, ZIP с секретами и резервные копии не размещаются
в публичной папке или репозитории. Для обновления достаточно заменить код;
меню и загруженные фотографии сохраняются отдельно.

## Приём заказов

Загрузка новой сборки сама по себе не включает настоящие заказы. Без приватного
`orders-config.php` оформление сообщает, что приём ещё не подключён. Перед
включением согласовать расписание, территорию, тарифы, минимум заказа, время
подготовки, предзаказ, адрес самовывоза и отдельные условия обработки данных
заказа. Текст клуба для этого не используется.

Скопировать пример настроек в приватную папку, заполнить согласованные значения
и заменить тестовый `order-terms.html` утверждённым документом. `enabled` и
`termsApproved` включать только после настройки и полной проверки обработки
заказов сотрудниками. Подключить токен, допуски, HTTPS webhook и cron по
[инструкции Telegram](telegram.md). Пока бот выключен, уведомления ожидают
настройки. Отправитель интегратору и онлайн-оплата пока отсутствуют.

SQLite должна находиться на локальном диске хостинга вне публичной папки.
Базу копировать согласованным SQLite backup-инструментом или при остановленном
приёме и отсутствии активных записей, затем проверить восстановление. Простое
копирование работающей базы во время записи не является надёжной резервной копией.
Сроки хранения данных и расписание резервных копий согласуются перед запуском.
Подробнее: [доставка](delivery.md).

## Проверка после переноса

Дополнительные сотрудники и автоматическое запоминание браузера поддерживаются PHP.
Рабочая сессия блокируется через 15 минут без действий и в любом случае завершается
через 8 часов. На запомненном браузере повторный вход требует свежий код приложения.
Cookie запоминания имеет технический срок до 400 дней, обновляемый только после
успешной проверки кода; отдельного 30-дневного ограничения серверной записи нет.
Браузер может удалить cookie раньше. Обычный «Выйти» сохраняет запоминание;
на общем компьютере используйте «Выйти и забыть устройство».
Локальные пароли, привязки телефона и cookie через Git/обычную сборку не переносятся.
Отдельный зашифрованный пакет переносит аккаунты, но очищает сессии и запомненные
устройства; после первого входа паролем и кодом браузер снова запоминается.
При обновлении
не заменяйте рабочие `admin-config.php` и `admin-data/`. Чтобы добавить сотрудника,
оператор запускает из SSH `php /путь/vosem-utra-private/app/add-admin.php /путь/vosem-utra-private employee@example.ru`.
Данные первого входа сохраняются только в приватном `admin-access-*.txt`; их нельзя
загружать в публичную папку. Сотрудник меняет временный пароль и подключает свой
аутентификатор. Подробности — `docs/admin-security.md` в исходниках проекта.

Проверить HTTPS без цикла перенаправлений, главную и все фотографии, вход с MFA,
добавление/скрытие блюда, загрузку фото, выход, отказ без авторизации и работу
формы клуба с согласованной тестовой анкетой. Локальные тесты не отправляют
реальных заявок в FlexBonus и не подтверждают действительность его ключей.

Меню и разметка для поисковиков обновляются PHP при каждом открытии главной,
поэтому новые цены и скрытие блюд не требуют повторной сборки. На основном
домене проверить canonical, robots.txt и sitemap.xml, затем отправить sitemap
в Яндекс Вебмастер и Google Search Console. Их проверочные токены можно задать
в приватном конфиге (`googleVerification`, `yandexVerification`).

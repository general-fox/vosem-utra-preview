# Тестовый сайт test888.ru — первая загрузка на REG.RU

Этот комплект предназначен только для https://test888.ru, не для сайта клиента.
Работают меню, фотографии, админка с двухфакторным входом, корзина и сохранение
тестовых заявок. Telegram исключён. Онлайн-оплата и регистрация в клубе отключены.
КДС подключается отдельным приватным конфигом по `kds-connection.md`; без него
заявки сохраняются только на стенде. Тестовые заказы не исполняются.
Используйте вымышленные контакты и адреса. Все страницы отдают noindex.

## 1. Подготовить хостинг

В ispmanager откройте «Сайты» → test888.ru и посмотрите «Корневой каталог».
Нужен PHP 8.3 или новее с cURL, OpenSSL, GD, PDO SQLite и fileinfo; memory_limit 512 МБ.
Для фото до 100 МБ загрузите `.user.ini` в корень сайта: upload_max_filesize 100M,
post_max_size 110M. Если эти настройки не применяются, задайте их в панели PHP.
Домен должен быть привязан к хостингу, SSL выпущен, а HTTPS открываться без ошибки.
Включите перенаправление HTTP → HTTPS в настройках сайта в панели REG.RU.
Используйте адрес без www: https://test888.ru. Перенаправление www при необходимости
тоже настраивается в панели, с сертификатом для обоих имён. Код не доверяет
присланному браузером X-Forwarded-Proto и не добавляет собственный HTTPS-редирект.

## 2. Распаковать архив на компьютере

Внутри есть две папки:

- `site` — публичные файлы сайта;
- `vosem-utra-private` — код PHP, настройки и данные админки. Эта папка приватная.

Персональный комплект первой установки содержит секреты в приватной папке.
Архив целиком не загружайте в публичный каталог сайта или GitHub.
Памятка со входом выдаётся отдельным файлом и вообще не загружается на хостинг.

## 3. Загрузить через файловый менеджер ispmanager

Откройте корневой каталог test888.ru. Содержимое папки `site` загрузите ВНУТРЬ него,
включая скрытый файл `.htaccess`. Саму папку `site` создавать там не нужно.
Если имеется стандартная заглушка `index.html`, переименуйте её в резервную копию
вне публичного каталога. Свою ранее загруженную рабочую копию сначала сохраните.

Затем перейдите НА ОДИН УРОВЕНЬ ВЫШЕ корневого каталога и загрузите туда папку
`vosem-utra-private` целиком. Пример для типового пути:

```text
/www/
├── test888.ru/                 ← корневой каталог сайта из панели
│   ├── .htaccess
│   ├── app.php
│   ├── staging.css
│   ├── assets/
│   └── ...остальное из site/
└── vosem-utra-private/         ← рядом с каталогом домена, НЕ внутри него
    ├── .htaccess
    ├── app/
    ├── admin-config.php
    ├── admin-data/
    ├── orders-config.php
    └── ...
```

Точное имя родительского каталога может отличаться. Важно взаимное расположение:
`app.php` ищет приватную папку рядом с корневым каталогом сайта.
Если там уже есть `vosem-utra-private` другого сайта, не объединяйте их —
нужно отдельно настроить путь для этого стенда.
PHP должен иметь право записи в `admin-data` и создания/записи `orders-data`.
Права 777 не нужны; используйте владельца файлов, под которым работает PHP.
База SQLite появится автоматически после обращения к оформлению заказа.

## 4. Проверить

1. Откройте https://test888.ru — видна пометка тестового сайта, блюда и фотографии.
2. Откройте https://test888.ru/admin — войдите по отдельной памятке доступа.
   Случайные посетители не могут создать себе аккаунт. Сначала проверяется пароль,
   затем код аутентификатора или защищённая настройка своего второго фактора.
3. Измените тестовую цену в админке и проверьте меню, затем верните цену.
4. Добавьте блюдо в корзину, оформите самовывоз с вымышленным телефоном
   +7 (000) 000-00-00 и подтвердите тестовые условия.
5. Получите номер TEST-… и сообщение «Сохранено на тестовом стенде».
   Повтор отправки после потери ответа не должен создавать второй заказ.
6. Проверьте доставку: без согласованного тарифа её итог остаётся неизвестным.

Условия пока демонстрационные: круглосуточные тестовые слоты, 30/60 минут
подготовки, без онлайн-оплаты. Это не утверждённые условия кофейни.
Просмотра очереди заказов в Telegram больше нет. На этом этапе результат
проверяется по экрану подтверждения; данные остаются в приватной SQLite.

## 5. Подключение КДС

Подготовлено отдельное обновление с приватным `kds-config.json` и двумя тестовыми
блюдами. Подключение и одноразовая настройка cron описаны в `kds-connection.md`.
Старые тестовые заявки не отправляются после подключения.
Общий пакет `build:reg:test` сам по себе не содержит сервисного пароля.

## Последующие обновления

Заменять только `site` и `vosem-utra-private/app`. Не перезаписывать рабочие
`admin-config.php`, `admin-data`, `orders-config.php`, `orders-data`.
Повторная загрузка полного первоначального комплекта вернёт старые учётные
данные и меню. Перед обновлениями делайте резервную копию серверных данных.

Разработчику: `npm run build:reg:test` создаёт общий пакет без учётных данных;
персональный доступ и актуальное меню добавляются отдельно локальным
`hosting/staging/prepare-test.php`. Рабочая сборка `build:reg` не изменена.

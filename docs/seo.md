# SEO для «Восемь утра»

Основной адрес подготовленной версии: `https://vosem-utra.ru/`.
Работы в репозитории не публикуют сайт, не меняют DNS и не отправляют страницы
на индексацию. Публичный GitHub-предпросмотр остаётся отдельной демонстрацией.

## Предпросмотр и основной сайт

Обычная сборка `npm run build` предназначена для предпросмотра и сохраняет
`noindex, nofollow` на всех HTML-страницах. Исходный `index.html`, который можно
показывать напрямую через GitHub Pages, также остаётся с `noindex`.

Режим Vite `hosting` создаёт отдельную сборку `dist-hosting` для основного домена.
Только главная страница в этом режиме получает `index, follow`, canonical
`https://vosem-utra.ru/`, метаданные Open Graph/Twitter и JSON-LD кофейни.
Страницы администратора, анкеты, политики и согласия сохраняют `noindex`.
Для политики и согласия разрешён переход по ссылкам (`follow`).

Для REG.RU команда `npm run build:reg` дополнительно собирает PHP-комплект
`dist-reg`. В нём `hosting/php/site.php` обновляет HTML меню и JSON-LD при
каждом запросе из приватного хранилища. Индексация разрешается только для
основного origin `https://vosem-utra.ru`; тестовые адреса всегда получают
`noindex` и пустой sitemap. Проверочные токены задаются в приватном
`admin-config.php`, поля `googleVerification` и `yandexVerification`.

Нельзя убирать `noindex` из демонстрации через JavaScript: робот может пропустить
исполнение скриптов после получения этой директивы. Решение об индексации
принимается при подготовке исходного HTTP-ответа.
[Google: особенности JavaScript и индексации](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

`robots.txt` разрешает обход HTML-страниц, чтобы робот увидел их `noindex`.
Запрещено только сканирование `/api/`; это правило не заменяет авторизацию.
В корневом файле исходников и в `public/robots.txt` нет `Disallow: /` и нет
неподдерживаемой директивы `Noindex:`. Robots-файл работает только в корне
соответствующего хоста; у GitHub Pages в подпапке репозитория основная защита
от индексации — метатеги самих HTML-страниц.
[Google: доступность страницы для чтения noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing),
[Яндекс: управление роботами через метатеги](https://yandex.ru/support/webmaster/ru/controlling-robot/metatags).

## Содержимое первого ответа

Главная содержит названия, описания, цены и локальные фотографии опубликованных
завтраков уже в HTML. Гости и роботы могут прочитать блюда без JavaScript;
браузерный модуль добавляет фильтры и обновление данных. Google отдельно
рекомендует учитывать серверный рендеринг и предварительное формирование HTML,
поскольку не все роботы выполняют JavaScript.
[Google: JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

В сборке используется проверенное меню `public/data/menu.json`. На работающем
сервере главная должна преобразовываться заново из актуального хранилища при
каждом запросе: скрытые и удалённые через админку блюда не должны оставаться
в старом HTML или JSON-LD после изменения меню.

`server/seo.mjs` содержит чистые функции без чтения окружения и диска:

```js
transformPage(html, {
  page: 'index',             // Также index.html, admin, registration, privacy, consent.
  production: false,         // Только строгое true включает production SEO.
  items: publishedOrAllItems,
  googleVerification: '',
  yandexVerification: '',
});

renderHomeSeo(html, items, options); // Главная, эквивалент transformPage.
renderMenu(items);                  // { grid, extras, count }.
renderRobots({ production });
renderSitemap({ production });
```

Преобразователь сам добавляет комментарии `SEO:DISH-GRID` и `SEO:DISH-EXTRAS`
в пустые контейнеры `data-dish-grid` и `data-dish-extras`. Повторный вызов
заменяет содержимое между маркерами. Сборка, затем живой HTTP-ответ используют
один и тот же механизм: карточки и метаданные не дублируются. Не удаляйте эти
маркеры HTML-минификатором. При изменении разметки контейнеров обновляйте тесты.
Если обязательный контейнер пропал, преобразователь сообщает об ошибке,
чтобы сборка не выпустила незаметно пустое меню.

Тексты экранируются для HTML, значения JSON-LD защищены от закрытия тега
`script`, фотографии ограничены локальными каталогами `menu-images` и `uploads`.
У нечисловых/отрицательных цен и неопубликованных позиций нет карточек.

## Факты и метаданные

Title и description содержат название кофейни, завтраки, адресную привязку
и часы работы из существующего сайта. JSON-LD использует тип `CafeOrCoffeeShop`
и следующие сведения:

- «Восемь утра», Москва, Шелепихинская набережная, 34, корпус 6;
- телефон `+7 (985) 130-81-06`;
- ежедневно `08:00–20:00`;
- адрес меню `https://vosem-utra.ru/#menu`;
- официальные ссылки на карточку Яндекс Карт и Telegram;
- опубликованные названия, описания и цены блюд в рублях.

Координаты, почтовый индекс, отзывы, рейтинг и ценовой диапазон не добавлены:
для них нет подтверждённых исходных данных. При изменении контактов или графика
обновляйте видимый блок контактов, `server/seo.mjs` и `hosting/php/site.php`.
Структурированные данные помогают передать сведения о заведении, но не
гарантируют отдельный расширенный результат в поиске.
[Google: разметка локальной организации](https://developers.google.com/search/docs/appearance/structured-data/local-business).

`public/social-cover.webp` — точная копия существующей фотографии
`assets/hero-two-cups-1254.webp`, 1254 × 1254 пикселя, около 371 КиБ.
Это стабильный публичный путь для карточек ссылок и JSON-LD; хешированные
имена ресурсов Vite на него не влияют. Новые изображения не генерировались.

Production sitemap содержит ровно один канонический URL — главную.
Якоря разделов, админка, анкета и правовые страницы туда не включаются.
У preview sitemap пустой, и preview robots не объявляет sitemap основного
домена. Не указываем выдуманные `lastmod`, приоритеты и частоту изменений.
[Google: создание карты сайта](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

## Подтверждение домена и последующий запуск

Токены Google Search Console и Яндекс Вебмастера не создаются автоматически.
Их выдаёт соответствующий сервис владельцу сайта. При наличии токенов
настройте `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION` в окружении сборки
и production-сервера. Интеграция передаёт значения в одноимённые по назначению
параметры `googleVerification` и `yandexVerification`. Метатеги появляются
только на production-главной и только для непустых настроенных значений.
Пустые поля и произвольные заглушки не подставляются.

После отдельного решения о публикации нужно развернуть production-сборку
и сервер на основном домене, настроить HTTPS и проверить фактический ответ
по `https://vosem-utra.ru/`: отсутствие `noindex`, canonical, цены и состав
опубликованных блюд, доступность robots/sitemap/social-cover. Затем владелец
может подтвердить домен и отправить sitemap в поисковые сервисы. Проверка
показа и индексация требуют уже доступного сайта; текущая подготовка кода
не выполняет эти внешние действия.

## Проверки в репозитории

```powershell
node --test tests/seo.test.mjs
```

Тесты проверяют preview/production, `noindex` служебных страниц, фактические
данные JSON-LD, первичный HTML блюд, повторный рендеринг после удаления
и скрытия позиций, экранирование, токены подтверждения, robots, sitemap
и исходный файл изображения. Интеграционные проверки сборки и HTTP-ответов
должны дополнительно проверять обе папки сборки и актуальность живого меню.
